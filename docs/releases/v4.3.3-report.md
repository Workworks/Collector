## 发布阻塞：签名不同

通过 GitHub CLI 下载官方仓库 v4.3.0 APK，下载文件 SHA-256 与 GitHub asset digest 一致：`78ea93db9afe80201b06a66d4dba918c407ce18a1d51694bcfc13e31855cdbee`。

`apksigner verify --print-certs` 两端均验证成功，但证书 SHA-256 不一致：

- GitHub v4.3.0：`03d73e71eb13c82a820dc50f4ef780630aa698591944693ff6b7c1c3c3bb013a`
- 本机 v4.3.3：`98edb36c3e227cec56d525ae9e3e7aeafbf653ebccdc923804dd2031b8b5097e`

两者证书名称都是 Android Debug，但名称相同不代表密钥相同。现有 v4.3.0 用户无法直接覆盖安装此候选包；不能要求用户卸载以绕过签名冲突，因为会丢失私有数据。

已检查项目/工作区内 keystore、jks 文件、仓库 HEAD 中的签名文件，以及本机用户标准 `.android/debug.keystore` 路径；仅找到当前用户的本机签名，未找到旧版对应签名。没有改写、覆盖或复制私钥到仓库，没有修改应用包名。

证据：[旧 APK 签名](evidence-v4.3.3/previous-signature.txt)、[新 APK 签名](evidence-v4.3.3/candidate-signature.txt)、[构建日志](evidence-v4.3.3/build.log)、[测试与哈希](evidence-v4.3.3/verification.json)。
