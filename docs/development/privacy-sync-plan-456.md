# 本地隐私与长期同步决策

2026-08-31，任务账本的“规划本地加密、应用锁和持久重试队列”输出。此文件是设计结论，不代表相应功能全部实现。

## 已核实的现状

- [SettingsStore](../../app/src/main/java/com/kfaino/diapertracker/SettingsStore.kt) 和 [MainActivity](../../app/src/main/java/com/kfaino/diapertracker/MainActivity.kt:180) 已有生物识别锁设置与入口；[BiometricLockHelper](../../app/src/main/java/com/kfaino/diapertracker/BiometricLockHelper.kt) 的会话状态不是完整后台重锁。此前“没有应用锁”的描述过宽，应改为“已有入口，覆盖范围和重锁未完整验收”。
- Android SharedPreferences 与桌面 JSON 没有整体加密；原 WebDAV 配置也不是加密保险库。操作系统账户可访问本地文件，界面隐藏和共享敏感过滤不能阻挡此威胁。
- 现有加密导出保护离线备份；家庭 HTTP 仅适合可信局域网，公网必须 HTTPS。不能因家庭白名单而声称全部网络请求都受同一策略限制。
- 原 WebDAV 上传有有限重试和条件写入，但没有可靠的持久上传任务状态机。失败后重启不能假定仍掌握远端版本。

## 决策与实现顺序

1. 先修完整入口锁：主界面、工作台、外部分享与小组件入口逐一验收；后台超时清空会话；设备认证不可用时拒绝读取敏感内容并明确提示，不静默放行。启用前验证恢复路径，避免用户失去全部访问能力。需要有锁屏凭据的物理设备验证，模拟器无认证不能代替。
2. 凭据先于业务库迁移：Android 使用 Android Keystore，Windows 使用当前用户 DPAPI；成功加密并回读校验后才移除明文。凭据不可跨设备解密时要求重新输入，不把新生成的密钥当成旧密钥。设备迁移、认证变化、损坏密文与断电必须回归。
3. 数据库加密后做：先输出可独立恢复的加密备份，使用版本化容器及暂存文件迁移，校验记录/附件/未知字段后一次替换。保留明确回滚机制；不直接给现有 JSON 套密码后宣布完成。
4. 持久重试队列只处理用户确认的上传：记录 taskId、快照哈希、目标、状态、attempt、nextAt 和条件 ETag，不保存明文密码。状态为 pending/running/succeeded/conflict/failed/cancelled；重启后的 running 回 pending，但必须重新核对远端。412 转 conflict，不自动重试覆盖；401 停止并要求更新凭据；取消删除队列引用而不删除业务数据。
5. Android 后台调度与桌面运行时调度分别落地，采用有上限退避；用户可见队列、手动重试和取消。不要使用永久服务或无限循环抵抗系统限制。长期系统调度必须以跨重启、断网、低电量及后台实际结果验收。

验收前置：真实设备认证、可恢复测试账号/凭据、离线备份、受控网络故障环境。当前不执行未经验证的原数据加密迁移，不悄悄启用后台上传；这些是独立实施项，不能因本设计完成而标记为已实现。
