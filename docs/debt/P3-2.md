# P3-2　DataStore 上帝对象拆分

**状态**：✅ 全部阶段已完成　**优先级**：P3

## 硬约束

`DataStore` 被全项目 60+ 处调用。**公开 API 一个都不能变，SharedPreferences key 一个都不能改。**

## 方案：保留门面（Facade），实现下沉

```
DataStore (facade 门面模式，325 行，公开 API 与 key 完全不变)
├── ✅ VaultRepositories   卡券/证照/药箱/生鲜/荣誉 五馆持久化   —— 已完成（402 行搬出）
├── ✅ SettingsStore       主题/触感/通知/简易模式/生物识别/WebDAV 凭据 —— 已完成（80 行下沉委托）
├── ✅ SpaceRepository     房屋、房间、平面图坐标持久化 —— 已完成（150 行下沉委托）
├── ✅ CategoryRepository  分类增删改与预设合并 —— 已完成（80 行下沉委托）
├── ✅ BackupCodec         exportBackupJson / importBackupJson —— 已完成（160 行下沉委托）
├── ✅ AnalyticsQueries    回血 ROI、安全库存、补货清单 —— 已完成（50 行下沉委托）
└── ✅ EntryRepository     物品/订阅 CRUD、退役、打卡、借还台账 —— 已完成（360 行下沉委托）
```

**做法**：把整段实现**原样**下沉进专用仓储（方法体逐字不改），
`DataStore` 里留同名同签名的一行委托。公开 API 与存储 key 天然不可能变。
